## Project Overview

**proyectoJuegoUNAD** is a Unity 6 game project for a multimedia engineering degree at UNAD (Universidad Nacional Abierta y a Distancia). It is a team repo: `README.md` holds per-member profiles (Elianis Manuel Medina – Level Designer; Jhon – Game Programmer; Geordany Giraldo Arenas), with their photos in `Elianis/`, `Jhon/`, `Geordany Giraldo Arenas/`. Docs and UI text are in Spanish.

## Repository Layout (read this first — it is non-obvious)

## Game Design / Code Architecture

The game is **"Guardianes del Bosque"**: an educational 3D low-poly game, being converted from a side-scroller to **third person** (see `Docs/ThirdPersonConversionPlan.md`; the drone game "Smog Buster" was removed). One level, three zones; the player runs and jumps, auto-collects waste (target 10), and must avoid hazards. The GDD is `proyectoJuegoUNAD/Assets/Docs/GuardianesdelBosqueGDD.md`; the roadmap is `Docs/ActionPlan.md` and the controller work is in `Docs/StarterAssetsIntegrationPlan.md`. Scenes: `Assets/Scenes/MainMenu.unity`, `Level01.unity`.

Code lives in `proyectoJuegoUNAD/Assets/Scripts/` and compiles into the **`ForestGuardian` assembly** (`ForestGuardian.asmdef`, references `Unity.StarterAssets` and `Unity.InputSystem`). Editor-only scripts must go in their own asmdef limited to the Editor platform; tests live in `Assets/Tests/EditMode` (pure logic, e.g. `GameSession`) and `Assets/Tests/PlayMode` (loads `Level01` and drives the player). Build Settings scene order: `MainMenu`, `Level01`.

- **Player:** `Player/PlayerController.cs` (formerly `SideScrollerController`, same GUID) is a trimmed copy of the Starter Assets `ThirdPersonController` (`CharacterController`, camera-relative movement on X and Z, coyote time and jump buffer; `MovementReference` overrides the camera, which PlayMode tests use via `PlayerTestRig.FaceCourse`). It locks the cursor while playing. It exposes `Stumble(direction)`, `AddSpeedModifier` / `RemoveSpeedModifier`, and `InputEnabled`, and disables its own input whenever the game session is not Playing. `PlayerAnimationEvents` relays footstep/land animation events from the `Model` child. Prefab: `Assets/Prefabs/Player/Player.prefab`; animator: `Assets/Animation/PlayerAnimator.controller` (Starter Assets controller plus `Slow`, `Stumble`, `Victory`, currently placeholder clips). `Assets/Starter Assets/` is the trimmed Unity Asset Store package "First Person + Third Person | Character Controllers" (Unity Companion License): only what the game uses was kept (`StarterAssetsInputs`, `StarterAssets.inputactions` with our added `Pause` action, the Idle/Walk/Run/Jump clips plus `Armature.fbx`, which is their shared avatar, and the footstep/landing sounds). Do not re-import the full package and do not run its menus.
- **Game state:** `Gameplay/GameSession.cs` is pure C# (Playing / Paused / Won / Lost, waste counter, events) and is the unit-tested core; `GameManager` is the scene singleton that owns it, applies `Time.timeScale` on pause and restarts the scene. `LevelConfig` (ScriptableObject, `Assets/Config/`) holds the target waste and the kill-plane Y. `KillPlane` ends the game when the player falls below that Y.
- **Hazards (`Environment/`):** `PlayerHazard` (trigger that stumbles the player), `RollingLog` (rolls along its own local X), `FallingRock` + `FallingRockTrigger` (shadow warning, then drop), `MudZone` (speed modifier). Ready-made prefabs are in `Assets/Prefabs/Hazards/` (`RollingLog_Hazard`, `FallingRock_Hazard`, `MudZone_Hazard`) and sit under the `Hazards` group of `Level01`; every hazard collider is a trigger on layer `Hazard`. Layers: `Ground`, `Hazard`, `Collectible`. Visual rule: things to avoid (obstacles, hazards) use the dark `Obstacle_Atlas` material; waste will be bright and saturated.
- **Camera:** Cinemachine 3 camera in `Level01`. The menu *Forest Guardian > Player > Set Up Third Person Camera* (`Scripts/Editor/ThirdPersonCameraSetup.cs`) turns the old side-view `CM Side Camera` into `CM Player Camera` (Orbital Follow, Rotation Composer, mouse / right stick orbit, auto-recentering behind the player) and turns the player toward the goal. `CameraBounds` only matters to the old side view.
- **Input:** the player uses `StarterAssets.inputactions` through `PlayerInput` (Send Messages): Move (A/D, arrows), Jump (Space), Pause (Esc). `InputSystem_Actions.inputactions` is a leftover and unused.
- **Level environment:** `Level01` is a winding forest trail (about 281 m, three zones by trail distance) generated by `Scripts/Editor/LevelEnvironmentBuilder.cs` (menu *Forest Guardian > Level > Build Level01 Environment*, Editor-only asmdef `ForestGuardian.Editor`). From its tables it builds, under `Environment`: the forest-floor mesh (`Assets/Generated/Level01_ForestFloor.asset`: 4 m dirt path, 12 m walkable corridor widened by clearings, earth banks ≤ 1.2 m, streams ≤ 2.6 m that lose if you fall in, kill plane y = −2), invisible walls (`PlayAreaBounds`), obstacles, ledges, scenery (trees inside the corridor get a `Trunk` collider) and a `ForestTrail` component with the centre line, which tests use to measure "distance along the trail". It also moves the hazards, the goal, the player, the cameras and **all waste under `Collectibles`** onto the trail. Running it again **discards hand edits under `Environment` and `Collectibles`**; change its tables instead. Art comes from the Asset Store pack "Low-Poly Simple Nature Pack" in `Assets/SimpleNaturePack` (only its two materials were edited, to URP/Lit); the game uses the variants in `Assets/Prefabs/Environment/`: `Scenery/` and `Terrain/` prefabs never have colliders, `Obstacles/` are solid on layer `Ground` and at most 1.2 m tall so they stay jumpable (tests enforce both). Details in `Docs/ThirdPersonConversionPlan.md` and `Docs/NaturePackIntegrationPlan.md`.
- **Look:** `Scripts/Editor/LevelAtmosphereSetup.cs` (menu *Forest Guardian > Level > Apply Level01 Atmosphere*) sets the sun, sky, ambient light, linear fog (starts at 24 m so the lane is never hazed) and the `Level01 Volume`, whose profile is `Assets/Config/Level01_VolumeProfile.asset`. Never edit the shared `Assets/Settings/DefaultVolumeProfile.asset` (Unity rewrites it during builds), and keep motion blur, film grain, chromatic aberration and lens distortion off (accessibility).
- **Collectibles (`Gameplay/Collectible.cs`):** touching one calls `GameSession.AddWaste()`, raises the static `Collectible.Collected` event and deactivates it; nothing counts once the game is over. Prefabs in `Assets/Prefabs/Collectibles/`: the base `Collectible` (sphere trigger r = 0.7 m on layer `Collectible`, empty `Visual` child that bobs and spins) and eight variants `Collectible_<Type>` holding the models from `Assets/Models/Waste/` (exported from the Blender file `Coleccionables.blend`) with URP materials in `Assets/Materials/Waste/`. Each model has a `*_Rim` material that emits above the bloom threshold. New waste types are new variants of the base prefab; `CollectiblePrefabPolicyTests` enforces the trigger, layer and glowing rim.
- **Goal and end screens:** winning needs `LevelConfig.targetWaste` collected **and** touching `LevelGoal` (trigger at the end of the course, x = 166.5); `GameSession.ReachGoal()` holds the rule and raises `GoalReachedWithMissingWaste` when the player arrives short. `UI/GameScreens.cs` (prefab `Assets/Prefabs/UI/GameScreens.prefab`, uGUI with legacy `Text`; the `ForestGuardian` asmdef references `UnityEngine.UI`) shows the win and lose panels with a restart button and the missing-waste notice. `Level01` has an `EventSystem` with `InputSystemUIInputModule`.
- **Status:** 12 collectibles are placed in `Level01` by `LevelEnvironmentBuilder` (3 / 4 / 5 per zone; at most two lie free on the path, in Zone 1, the rest are up high, on a ledge, over a stream or next to a hazard). Audio: the `LevelAudio` object in `Level01` (`Scripts/Audio/LevelAudio.cs`) crossfades the ambient loops in `Assets/Sound/Ambient/` and plays `Assets/Sound/SFX/collectible_pickup_sound.wav` on `Collectible.Collected`; both are 2D, and pausing lowers the ambience. Phases A–D and F of `Docs/NaturePackIntegrationPlan.md` are done (materials, prefab variants, level layout, hazard art, lighting); phase E (polluted-to-recovered look, needs the collectibles) and G (licences and QA) remain.

## Commands

There is no CLI build, lint, or test script. Everything runs through the Unity Editor:

- **Open:** Unity Hub → add `proyectoJuegoUNAD/` → Unity 6000.5.6f1.
- **Play:** Play button in the Editor.
- **Build:** File > Build Profiles (Build Settings).
- **Tests:** Window > General > Test Runner (Test Framework package; EditMode tests for `GameSession`, PlayMode tests for the player and game state). Headless, if needed: `Unity.exe -batchmode -projectPath proyectoJuegoUNAD -runTests -testPlatform EditMode -quit`.
- **Unity MCP** (`mcp__unity-mcp__*`) is configured and can read console logs, run editor commands, and capture the scene/camera — useful for verifying changes without leaving the CLI.

## Conventions

- New scripts go under `Assets/Scripts/<Feature>/` (`Player`, `Environment`, `Gameplay`, `UI`, `Editor`), one responsibility per script.
- Input goes through the Input System (`Assets/InputSystem_Actions.inputactions`), not the legacy `Input` class.
- **`.meta` files must ALWAYS be committed, in the same commit as their asset (or folder).** Each `.meta` holds the asset's GUID; if it is missing, every teammate's Unity generates a different GUID, scene/prefab references break, and merges corrupt the project. Never add `*.meta` to `.gitignore`, never delete a `.meta` by hand, and move/rename assets inside Unity (or move the asset and its `.meta` together). When creating files outside the Editor (scripts, docs), the `.meta` appears once Unity next focuses — commit it before pushing.
- Never commit `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `.vs/`, or generated `*.csproj`/`*.sln`.
- Active branch for this developer is `elianis-medina`; `main` is the PR target.
