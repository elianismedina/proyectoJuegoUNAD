# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**proyectoJuegoUNAD** is a Unity 6 game project for a multimedia engineering degree at UNAD (Universidad Nacional Abierta y a Distancia). It is a team repo: `README.md` holds per-member profiles (Elianis Manuel Medina – Level Designer; Jhon – Game Programmer; Geordany Giraldo Arenas), with their photos in `Elianis/`, `Jhon/`, `Geordany Giraldo Arenas/`. Docs and UI text are in Spanish.

## Repository Layout (read this first — it is non-obvious)

## Game Design / Code Architecture

The game is **"Guardianes del Bosque"**: an educational 3D low-poly game, being converted from a side-scroller to **third person** (see `Docs/ThirdPersonConversionPlan.md`; the drone game "Smog Buster" was removed). One level, three zones; the player runs and jumps, auto-collects waste (target 10), and must avoid hazards. The GDD is `proyectoJuegoUNAD/Assets/Docs/GuardianesdelBosqueGDD.md` (published as a web page at https://elianismedina.github.io/proyectoJuegoUNAD/ by `.github/workflows/gdd-pages.yml` with pandoc and `.github/gdd-site/style.css`, rebuilt on every push to main that touches it); the roadmap is `Docs/ActionPlan.md` and the controller work is in `Docs/StarterAssetsIntegrationPlan.md`. Scenes: `Assets/Scenes/MainMenu.unity`, `Level01.unity`.

Code lives in `proyectoJuegoUNAD/Assets/Scripts/` and compiles into the **`ForestGuardian` assembly** (`ForestGuardian.asmdef`, references `Unity.StarterAssets` and `Unity.InputSystem`). Editor-only scripts must go in their own asmdef limited to the Editor platform; tests live in `Assets/Tests/EditMode` (pure logic, e.g. `GameSession`) and `Assets/Tests/PlayMode` (loads `Level01` and drives the player). Build Settings scene order: `MainMenu`, `Level01`.

- **Player:** `Player/PlayerController.cs` (formerly `SideScrollerController`, same GUID) is a trimmed copy of the Starter Assets `ThirdPersonController` (`CharacterController`, camera-relative movement on X and Z, coyote time and jump buffer; `MovementReference` overrides the camera, which PlayMode tests use via `PlayerTestRig.FaceCourse`). Every jump plays one of `JumpAudioClips` at random (`Assets/Sound/SFX/JumpAudio1.mp3`, `jumpAudio2.mp3`, `JumpAudio3.mp3` from Jhon's PR #41, assigned on `Prefabs/Player/Player.prefab`, `JumpAudioVolume` 0.7) on a 2D `AudioSource` the controller creates on a "Jump Audio" child (`JumpAudioSource`, `JumpSoundsPlayed`, `LastJumpClip` for tests; footsteps and landing still use the Starter Assets 3D `PlayClipAtPoint`). It locks the cursor while playing. It exposes `Stumble(direction)`, `AddSpeedModifier` / `RemoveSpeedModifier`, and `InputEnabled`, and disables its own input whenever the game session is not Playing. A stumble (from a `PlayerHazard`, or from running head-on into anything with the `Environment/Obstacle` marker, detected in `OnControllerColliderHit`: side contact only, at ≥ `ObstacleHitSpeed` 3 m/s toward it) takes control away for 0.5 s, then leaves the player at `StumbleSlowMultiplier` 0.5 speed for `StumbleSlowDuration` 1.5 s (`IsSlowedByStumble`, shown with the `Slow` animation); further hits are ignored for 1 s after the stumble. It raises the static `Stumbled` event. `PlayerAnimationEvents` relays footstep/land animation events from the `Model` child. `JumpShadow` (on the prefab, material `Assets/Materials/Player_JumpShadow.mat`) draws a flat dark disc straight below the player on the `Ground` layer so jump landings can be judged in 3D; it shrinks with height and hides over streams. Prefab: `Assets/Prefabs/Player/Player.prefab`; animator: `Assets/Animation/PlayerAnimator.controller` (Starter Assets controller plus `Slow`, `Stumble`, `Victory`, currently placeholder clips). `Assets/Starter Assets/` is the trimmed Unity Asset Store package "First Person + Third Person | Character Controllers" (Unity Companion License): only what the game uses was kept (`StarterAssetsInputs`, `StarterAssets.inputactions` with our added `Pause` action, the Idle/Walk/Run/Jump clips plus `Armature.fbx`, which is their shared avatar, and the footstep/landing sounds). Do not re-import the full package and do not run its menus.
- **Game state:** `Gameplay/GameSession.cs` is pure C# (Playing / Paused / Won / Lost, waste counter, events) and is the unit-tested core; `GameManager` is the scene singleton that owns it, applies `Time.timeScale` on pause and restarts the scene. `LevelConfig` (ScriptableObject, `Assets/Config/`) holds the target waste and the kill-plane Y. `KillPlane` catches the player below that Y (a stream) and, instead of ending the game, puts them back at the `Gameplay/Checkpoint` of the zone they fell in (`Checkpoint.ForZone`, by `ForestTrail.ZoneAt` of the fall point), at rest and facing down the trail (`PlayerController.Respawn`), snaps the Cinemachine orbit behind them (so the `ForestGuardian` asmdef references `Unity.Cinemachine`) and raises `KillPlane.PlayerRespawned`; the waste count and game state are untouched. Nothing in `Level01` reaches `Lost` any more (only a scene without checkpoints would); the lose screen and sound stay, tested by calling `GameManager.Lose()`.
- **Hazards (`Environment/`):** `PlayerHazard` (trigger that stumbles the player), `Obstacle` (marker on the root of every prefab in `Assets/Prefabs/Environment/Obstacles/`, enforced by `EnvironmentPrefabPolicyTests`, so running into it stumbles the player too), `RollingLog` (3D sounds on the `RollingLog_Hazard` prefab: `rollSound` loops `Assets/Sound/Ambient/GolpesTronco.mp3` while it rolls and pauses with the game, `bumpSound` plays `impactWood02.mp3` at each end of the run, `BumpsPlayed` for tests; rolls along its own local X; `Travel`, `Origin` and `RunAxis` expose its run). `LevelEnvironmentBuilder.RollingLogs` gives each `RollingLog_Hazard` in the `Hazards` group (in name order) its own spot: s 115 across the path (travel 9), s 158 along it (14), s 222 along the top of the last bank (9) and s 244.5 across (9). None in Zone 1. Each run is reserved so scenery, flowers and animals keep off it; `HazardPlayModeTests.RollingLogs_AreSpreadOutAndRunClear` checks they are spread out and that nothing solid, no waste, checkpoint or other hazard lies along any run (they used to be stacked at s 158), `FallingRock` + `FallingRockTrigger` (shadow warning, then drop), `MudZone` (speed modifier). Ready-made prefabs are in `Assets/Prefabs/Hazards/` (`RollingLog_Hazard`, `FallingRock_Hazard`, `MudZone_Hazard`) and sit under the `Hazards` group of `Level01`; every hazard collider is on layer `Hazard` and is a trigger, except the rolling log's `Body` child, a solid capsule covering the whole log so the player cannot walk through it (`RollingLog` also pushes the player out when it rolls into them). Layers: `Ground`, `Hazard`, `Collectible`. Visual rule: things to avoid (obstacles, hazards) use the dark `Obstacle_Atlas` material; waste will be bright and saturated.
- **Camera:** Cinemachine 3 camera in `Level01`. The menu *Forest Guardian > Player > Set Up Third Person Camera* (`Scripts/Editor/ThirdPersonCameraSetup.cs`) turns the old side-view `CM Side Camera` into `CM Player Camera` (Orbital Follow, Rotation Composer, mouse / right stick orbit bound to Cinemachine's own `CM Default/Look` action with low gain and eased accel/decel, slow auto-recentering behind the player: wait 2.5 s, time 4 s, so holding A/D turns the view gently instead of spinning it) and turns the player toward the goal. Tune those constants in the script and re-run the menu rather than editing the scene. `CameraBounds` only matters to the old side view.
- **Input:** the player uses `StarterAssets.inputactions` through `PlayerInput` (Send Messages): Move (A/D, arrows), Jump (Space), Pause (Esc). `InputSystem_Actions.inputactions` is a leftover and unused.
- **Level environment:** `Level01` is a winding forest trail (about 281 m, three zones by trail distance) generated by `Scripts/Editor/LevelEnvironmentBuilder.cs` (menu *Forest Guardian > Level > Build Level01 Environment*, Editor-only asmdef `ForestGuardian.Editor`). From its tables it builds, under `Environment`: the forest-floor mesh (`Assets/Generated/Level01_ForestFloor.asset`: 4 m dirt path, 12 m walkable corridor widened by clearings, earth banks ≤ 1.2 m, streams ≤ 2.6 m that send you back to the zone's checkpoint if you fall in, kill plane y = −2), invisible walls (`PlayAreaBounds`), obstacles (single ones from `Obstacles`, plus `Barriers` that close the way: a log across the path, a three-log fence across the whole corridor, rows of rocks or stumps with gaps narrower than the player; plus `HandPlaced`, six rocks Jhon placed by hand on main, kept because they repeat no barrier and crowd no waste or checkpoint; 13 / 14 / 16 obstacles per zone), ledges, one `Checkpoint` per zone under `Checkpoints` (table `Checkpoints`: Zone 1's is the spawn point, the others a few metres into their zone on clear path), scenery (trees inside the corridor get a `Trunk` collider) and a `ForestTrail` component with the centre line, which tests use to measure "distance along the trail". It also moves the hazards, the goal, the player, the cameras and **all waste under `Collectibles`** onto the trail. Running it again **discards hand edits under `Environment` and `Collectibles`**; change its tables instead (an obstacle placed only in the scene disappears on the next build: put it in `HandPlaced` or `Obstacles`). Art comes from the Asset Store pack "Low-Poly Simple Nature Pack" in `Assets/SimpleNaturePack` (only its two materials were edited, to URP/Lit); the game uses the variants in `Assets/Prefabs/Environment/`: `Scenery/` and `Terrain/` prefabs never have colliders, `Obstacles/` are solid on layer `Ground` and at most 1.2 m tall so they stay jumpable (tests enforce both). Details in `Docs/ThirdPersonConversionPlan.md` and `Docs/NaturePackIntegrationPlan.md`.
- **Forest recovery (GDD §6.1.4):** `Gameplay/ZoneRecoveryTracker.cs` is the pure, EditMode-tested rule (waste per zone; a zone is recovered when its last item is collected; a zone without waste starts recovered; `OverallProgress` is the average of the zones' progress; `RecoverAll` on a win). `Environment/ForestRecovery.cs`, added to the `Environment` root by `LevelEnvironmentBuilder`, counts each zone's waste at level start (by `ForestTrail.ZoneAt`), dresses the scenery of every zone under `Environment/Scenery` in `pollutedMaterial` (`Assets/Materials/Recovery/Nature_Polluted.mat`, the nature atlas tinted dull brown, created once by the builder and never overwritten, so Geordany can replace its art), swaps a recovered zone back to `healthyMaterial` (`SimpleNaturePack_Texture_01`), recovers everything on a win, and raises the static `ZoneRecovered(int)` / `ProgressChanged(float)` events (`ForestRecovery.Current` for the loaded level). It is a runtime shared-material swap, so the editor still shows the healthy look; the ground and the far hills never change. Recovery also makes the zone bloom: the flowers under `Environment/Recovery/Zone1..3` (variants `Assets/Prefabs/Environment/Recovery/Recovery_Daisy|Dandelion|Hyacinth|Rose` of the "Low Poly Flower Pack" demo by Emilulz in `Assets/Emilulz_Assets/DEMOLowPolyFlowers`, scale 0.55, no colliders, URP/Lit; vendor files untouched) start at scale 0 and grow in with a small overshoot, staggered over `growSpread` 1 s, `growSeconds` 0.6 s each (game time); `LevelEnvironmentBuilder.BuildRecoveryFlowers` places them (own seed 11, 16 patches of 4–7 per zone, about 80–90 flowers, off the path and at least 1 m from waste, checkpoints and anything solid), and `ForestRecovery.FlowersInZone` / `FlowersHidden` / `FlowersBloomed` expose them to tests. Flowers are not static (they are scaled at runtime). Each stream has running water: `BuildStreams` adds a `RiverSound` child (3D looping `Assets/Sound/Ambient/river.mp3`, volume 0.7, linear 4–12 m) at the path crossing. The five MP3s (river, GolpesTronco, impactWood02, Naturaleza-02, Avez) came from Jhon's PR #39, which was hand-edited into Level01 and is superseded by this builder / prefab wiring. Recovery also brings animals out: `Environment/RecoveryAnimals/Zone1..3` holds 4 per zone (`LevelEnvironmentBuilder.BuildRecoveryAnimals`, own seed 13; variants `Assets/Prefabs/Environment/RecoveryAnimals/RecoveryAnimal_Deer|Dog|Kitty|Chicken|Horse` of the "Animals FREE - Animated Low Poly 3D Models" pack by ithappy in `Assets/ithappy/Animals_FREE` (vendor files untouched; the variants drop the pack's `CharacterController`, `CreatureMover` and `MovePlayerInput`, turn off root motion, keep the pack's animator controller and URP/Lit material, and add `Environment/RecoveryAnimal.cs`). Each animal stands in the corridor at least `AnimalPathMargin` 1.5 m past the path's edge and `AnimalClear` 2 m from reserved spots (waste, checkpoints, obstacles, hazards), with an `OverlapCapsule` clear of anything solid; every other one is a walker whose 3 m stretch along the trail is checked at both ends and in between and must be fairly level, otherwise it rests. `RecoveryAnimal` drives the pack's blend tree (`Vert` 0 idle / 1 walk, `State` 0): a walker paces `PointA` ↔ `PointB` at 0.6 m/s, turning first and resting 2–5 s at each end; a rester idles at `PointA`. `ForestRecovery.animalsRoot` keeps them inactive while their zone is polluted, then activates them and grows them in like the flowers (also on a win); `AnimalsInZone` / `AnimalsHidden` / `AnimalsShown` expose them to tests (`ForestRecoveryPlayModeTests`, `EnvironmentPrefabPolicyTests.RecoveryAnimals_AreAnimatedDecorationWithoutCollidersOrPlayerScripts`). The pack's import also added `com.unity.postprocessing` (for its Built-In demo scene); the game does not use it. Every pickup also sprouts flowers where the waste was: `Environment/PickupBloom.cs` (added to the `Environment` root by the builder with the same four `Recovery_*` prefabs) listens to `Collectible.Collected` and spawns `flowersPerPickup` 5 flowers under `Environment/PickupFlowers`, growing in over 0.5 s each, 0.08 s apart; they grow on the `ForestFloor` below the item, never within `PickupBloom.PathClearance` 2.4 m of the trail centre (an item above the path sprouts a patch on each edge) and, for an item over a stream, on the nearer bank. Each sprouting plays `Assets/Sound/SFX/flowers_sound.wav` once (`PickupBloom.bloomClip`, set by the builder; 2D AudioSource on `PickupFlowers`, `BloomSoundsPlayed` for tests). `PickupBloomPlayModeTests` covers both cases. On `ZoneRecovered`, while Playing (not on the win, which recovers everything at once), `GameScreens` shows "¡Zona recuperada!" (`GameScreens.ZoneRecoveredMessage`) for about 2 s with a fade, and plays `Assets/Sound/SFX/sonido_zona_recuperada.wav` (a generated 0.6 s two-note placeholder chime) from an AudioSource on the `GameScreens` canvas; the notice is built into `GameScreens.prefab` by *Forest Guardian > UI > Build Zone Notice* (`Scripts/Editor/ZoneNoticeBuilder.cs`) at y −150, 700 × 100, between the goal arrow and the objective banner and right of the counter (`ZoneNoticeTests` checks it overlaps none of them). Polluted / clean ambience: `LevelAudio` loops `pollutedClip` (`Assets/Sound/Ambient/bosque_contaminado_sound.wav`, `pollutedVolume` 0.15 in Level01, like `ambientVolume`) while the player's zone (`ForestTrail.ZoneAt` of the player) is not recovered, and crossfades with the living-forest loops over `zoneFadeSeconds` 3 s (unscaled) when it is recovered or the player walks into a recovered / polluted zone (`PollutedMix` 0..1; snaps on the first frame, so the level starts polluted; without a `ForestRecovery` it stays alive). The tiered unlocking of zones is not built.
- **Look:** `Scripts/Editor/LevelAtmosphereSetup.cs` (menu *Forest Guardian > Level > Apply Level01 Atmosphere*) sets the sun, sky, ambient light, linear fog (starts at 24 m so the lane is never hazed) and the `Level01 Volume`, whose profile is `Assets/Config/Level01_VolumeProfile.asset`. Never edit the shared `Assets/Settings/DefaultVolumeProfile.asset` (Unity rewrites it during builds), and keep motion blur, film grain, chromatic aberration and lens distortion off (accessibility).
- **Collectibles (`Gameplay/Collectible.cs`):** touching one calls `GameSession.AddWaste()`, raises the static `Collectible.Collected` event and deactivates it; nothing counts once the game is over. Prefabs in `Assets/Prefabs/Collectibles/`: the base `Collectible` (sphere trigger r = 0.7 m on layer `Collectible`, empty `Visual` child that bobs and spins) and eight variants `Collectible_<Type>` holding the models from `Assets/Models/Waste/` (exported from the Blender file `Coleccionables.blend`) with URP materials in `Assets/Materials/Waste/`. Each model has a `*_Rim` material that emits above the bloom threshold. The base prefab also has a `Beacon` child (on the root, so it does not bob or spin): a 7 m additive light beam starting just above the model and a few slow sparkles, so waste can be spotted from far down the trail; it is built by *Forest Guardian > Collectibles > Build Waste Beacon* (`Scripts/Editor/CollectibleBeaconBuilder.cs`, which generates `Assets/Generated/Collectible_Beam*` / `Collectible_Sparkle.png` and the two `Collectible_*.mat` in `Assets/Materials/Waste/`; tune its constants and re-run rather than editing the prefab). New waste types are new variants of the base prefab; `CollectiblePrefabPolicyTests` enforces the trigger, layer, glowing rim and beacon.
- **Goal and end screens:** winning needs `LevelConfig.targetWaste` collected **and** touching `LevelGoal` (trigger at the end of the course, x = 166.5); `GameSession.ReachGoal()` holds the rule and raises `GoalReachedWithMissingWaste` when the player arrives short. `UI/GameScreens.cs` (prefab `Assets/Prefabs/UI/GameScreens.prefab`, uGUI with legacy `Text`; the `ForestGuardian` asmdef references `UnityEngine.UI`; Jhon's HUD styling from main lives as overrides on the `GameScreens` instance in `Level01`: the taller counter panel with a recycling icon and a "Recuperación del bosque" bar that `WasteCounter.progressBarFill` fills with `ForestRecovery.Progress` (falls back to collected / target in a scene without a `ForestRecovery`), icons in `Assets/UI_Icons/`, and the restyled objective banner; the banner and notice sit at y −350 / −330 to stay below that 186 px counter) shows the objective banner when the level starts ("Objetivo: Recoge 10 residuos y llega a la meta", built from `TargetWaste`; it stays about 5 s of game time, fades out, and gives way to the missing-waste notice or the end screens), the win and lose panels with a restart button, the notice panel (missing waste at the goal, or `GameScreens.RespawnNotice` "¡Te caíste! Vuelves al inicio de la zona con tus residuos." after a fall), and the pause menu (Esc: "Continuar" / "Reiniciar" / "Salir"; `GameManager.TogglePause` / `Resume` / `QuitToMenu`). The same prefab holds the HUD `GoalCompass` (`UI/GoalCompass.cs`, built by *Forest Guardian > UI > Build Goal Compass*, `Scripts/Editor/GoalCompassBuilder.cs`, which also draws `Assets/Generated/HUD_GoalArrow.png`; it lives in the prefab so it never touches `Level01.unity`): a small arrowhead at the top centre that points, relative to the camera, at the trail 10 m ahead of the player (the `LevelGoal` itself near the end), and after 1 s of running back along the trail (`GoalCompass.IsGoingBack`: ≥ 1 m/s against the trail tangent and mostly backwards) turns orange with "Vas en sentido contrario" beside it; hidden unless Playing, nothing flashes. `Level01` has an `EventSystem` with `InputSystemUIInputModule`.
- **Main menu:** `MainMenu.unity` (build index 0) holds a canvas built by *Forest Guardian > UI > Build Main Menu* (`Scripts/Editor/MainMenuBuilder.cs`, which saves the scene; running it again discards hand edits under `MainMenuCanvas`): title, the goal in one line, the controls, and "Jugar" / "Salir" in the same palette as `GameScreens`. `UI/MainMenu.cs` loads `Level01`, frees the cursor and resets `Time.timeScale`. The editor asmdef references `UnityEngine.UI` and `Unity.InputSystem` for it.
- **Status:** 12 collectibles are placed in `Level01` by `LevelEnvironmentBuilder` (3 / 4 / 5 per zone), and **every one needs a jump**: hung 1.9–2.5 m above the path (out of reach of the 1.6 m capsule on foot, inside a 1.7 m jump), over a stream more than 1 m from both banks, high in a clearing, or on a ledge rock; `LevelCollectiblesPlayModeTests.EveryWaste_NeedsAJump` checks every spot the player could stand within reach. Audio: the `LevelAudio` object in `Level01` (`Scripts/Audio/LevelAudio.cs`) plays the recovered-forest loop `Assets/Sound/Ambient/sonido_bosque_recuperado.wav` as its only `ambientClips` entry (a single clip simply loops; the old `ambient_sound_one` / `ambient_sound_two` are no longer used), fading it against `bosque_contaminado_sound` by zone (see Forest recovery); `recoveredLayerClips` (`Naturaleza-02.mp3` and `Avez.mp3`, `recoveredLayerVolume` 0.1, set by `LevelEnvironmentBuilder.ConfigureLevelAudio` on every rebuild) each loop on their own 2D source and fade with the living ambience (`RecoveredLayerVolume` for tests). It plays `Assets/Sound/SFX/collectible_pickup_sound.wav` on `Collectible.Collected`, plus one-shots from the same folder for the game events: `sonido_tropezar` on `PlayerController.Stumbled` (only hits that knock the player back), `sonido_llegar_meta` on `GameSession.GoalReachedWithMissingWaste`, `sonido_ganar` / `sonido_perder` when the state turns Won / Lost, and `sonido_perder` also on `KillPlane.PlayerRespawned` (a fall into a stream). All are 2D; pausing lowers the ambience, and so does the end of the game. Phases A–D and F of `Docs/NaturePackIntegrationPlan.md` are done (materials, prefab variants, level layout, hazard art, lighting); phase E (polluted-to-recovered look) is done in a first version (`ForestRecovery`, above: placeholder polluted material, blooming flowers) and G (licences and QA) remains.

## Commands

There is no CLI build, lint, or test script. Everything runs through the Unity Editor:

- **Open:** Unity Hub → add `proyectoJuegoUNAD/` → Unity 6000.5.6f1.
- **Play:** Play button in the Editor.
- **Build:** File > Build Profiles (Build Settings).
- **Tests:** Window > General > Test Runner (Test Framework package; EditMode tests for `GameSession`, PlayMode tests for the player and game state). Headless, if needed: `Unity.exe -batchmode -projectPath proyectoJuegoUNAD -runTests -testPlatform EditMode -quit`.
- **Unity MCP** (`mcp__unity-mcp__*`) is configured and can read console logs, run editor commands, and capture the scene/camera — useful for verifying changes without leaving the CLI.

## Conventions

- New scripts go under `Assets/Scripts/<Feature>/` (`Player`, `Environment`, `Gameplay`, `UI`, `Editor`), one responsibility per script.
- Input goes through the Input System (`Assets/InputSystem_Actions.inputactions`), not the legacy `Input` class.
- **`.meta` files must ALWAYS be committed, in the same commit as their asset (or folder).** Each `.meta` holds the asset's GUID; if it is missing, every teammate's Unity generates a different GUID, scene/prefab references break, and merges corrupt the project. Never add `*.meta` to `.gitignore`, never delete a `.meta` by hand, and move/rename assets inside Unity (or move the asset and its `.meta` together). When creating files outside the Editor (scripts, docs), the `.meta` appears once Unity next focuses — commit it before pushing.
- Never commit `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `.vs/`, or generated `*.csproj`/`*.sln`.
- Active branch for this developer is `elianis-medina`; `main` is the PR target.
